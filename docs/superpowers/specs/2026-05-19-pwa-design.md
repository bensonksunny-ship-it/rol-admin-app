# PWA — Installable + Resilient
**Date:** 2026-05-19
**Status:** Approved

---

## Goal

Convert the ROL Admin app into an installable Progressive Web App with a native standalone fullscreen experience. The app shell (HTML/JS/CSS/fonts) is cached for fast reloads. Firebase live data still requires a network connection. Firestore offline persistence is explicitly out of scope but must remain easy to add later.

---

## Scope

**In scope:**
- Web App Manifest (install support, standalone display)
- App icon set (192, 512, maskable, Apple touch)
- Service worker via `vite-plugin-pwa` + Workbox (app shell precaching)
- Offline detection banner in the React app
- PWA meta tags in `index.html`

**Out of scope:**
- Firestore offline persistence (`enableIndexedDbPersistence`)
- Push notifications
- Background sync
- Install prompt UI (browser native prompt is sufficient)

## Icon Set

All icons derived from a single SVG master: white "R" (serif, weight 900) centred on a dark navy gradient (`#0f172a` → `#1e3a8a`), rounded rect shape.

| File | Size | Purpose |
|---|---|---|
| `public/favicon.svg` | SVG | Browser tab |
| `public/icons/pwa-192.png` | 192×192 | Android home screen |
| `public/icons/pwa-512.png` | 512×512 | Android splash / Play Store |
| `public/icons/pwa-512-maskable.png` | 512×512 | Android adaptive icon (10% safe-zone padding) |
| `public/icons/apple-touch-icon.png` | 180×180 | iOS home screen |

Icons are generated by a one-time Node script (`scripts/generate-icons.cjs`) using `sharp` (SVG → PNG rasterisation). `sharp` is installed as a dev dependency and removed after icon generation if desired. The script is committed but only needs to be re-run if the icon design changes.

## Service Worker

Built with **`vite-plugin-pwa`** (`registerType: 'autoUpdate'`). Workbox handles precaching and runtime strategies.

### Precache (app shell)
All build output: `**/*.{js,css,html,ico,png,svg,woff,woff2}`. Versioned by Workbox manifest hash — stale assets are replaced automatically on deploy.

### Runtime caching

| URL pattern | Strategy | TTL / Notes |
|---|---|---|
| `fonts.googleapis.com/*` | CacheFirst | 365 days |
| `fonts.gstatic.com/*` | CacheFirst | 365 days |
| `*.firebaseio.com/*` | NetworkOnly | Never cache |
| `firestore.googleapis.com/*` | NetworkOnly | Never cache |
| `identitytoolkit.googleapis.com/*` | NetworkOnly | Auth — never cache |
| `cloudfunctions.net/*` | NetworkOnly | Never cache |
| All other navigation | Serve `index.html` | SPA fallback |

### Update behaviour
`registerType: 'autoUpdate'` — the service worker updates silently in the background. No user prompt needed for this admin tool.

## Offline Banner

A single `OfflineBanner` component listens to the browser `online`/`offline` events and `navigator.onLine`.

- **Shown:** fixed bar at the bottom of the screen, dark navy background, `📡 You're offline — live data unavailable. Reconnect to sync.`
- **Hidden:** when `navigator.onLine` is true; disappears automatically on reconnect
- **Z-index:** 50 (above page content, below modals)
- Mounted once in `App.jsx` outside the router so it is always visible regardless of route

The app shell continues to function from cache while offline. Firebase operations will fail with their own errors — the banner gives users context so they don't think the app is broken.

## Upgrade Path to Offline-First (future)

When ready to add Firestore offline persistence:
1. Enable `initializeFirestore(app, { localCache: persistentLocalCache() })` in `src/lib/firebase.js`
2. Change the Firestore runtime cache strategy from `NetworkOnly` to `NetworkFirst`
3. No service worker structural changes needed — `vite-plugin-pwa` config stays the same
